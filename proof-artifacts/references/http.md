# HTTP 接口验收证据

让审阅者在一页内核对实际发送的参数、返回的数据和用例的预期结果。每条证据都能追溯到一次已执行的 HTTP 交互。

## 采集实际交互

1. 从任务和仓库约定确认环境、接口入口、测试身份及允许使用的数据。记录实际地址和可确认的版本。按测试环境标记真实依赖与离线替身。
2. 优先用 Hurl 发起已授权的用例。采集或迁移 Hurl 记录时，读 [Hurl 采集说明](hurl.md)。本机测试客户端也可直接记录它实际发送的请求和接收的响应。
3. 每次交互保存请求方法、实际 URL、请求头和完整请求体，以及 HTTP 状态行、响应头和完整响应体。会话追问、历史回查、断言失败与非 2xx 响应各自成对保留。保留非法 JSON、空白字符和重复参数。SSE 正文按接收顺序保存所有字段和事件。
4. 选择允许归档的测试数据。对凭据、Cookie 和受保护数据做最小范围脱敏，并在用例页标明脱敏位置。只剩摘要、连接未收到响应或流中断时，标明缺失的证据和原因。有授权时重跑，将新交互记为新的一轮。

## 生成审阅页

使用清楚的用例名，并保留下列文件。

```text
proof-artifacts/<run>/
  README.md
  <case>/
    README.md
    request.hurl
    request.http
    response.http
```

`request.hurl` 用于 Hurl 用例。`request.http` 和 `response.http` 保留配对的实际交互。审阅页直接展示方法和 URL、适用的路径参数与查询参数、业务请求头、完整请求体，随后展示响应状态和可读正文。JSON 正文在页内缩进。SSE 用完整原文保留事件顺序，需要时再把业务结果事件单独缩进展示。完整记录用相对链接打开。

已有可分享的 HTTP 文件时，可用 Python 3 运行[审阅页生成器](../scripts/render_case.py)。下例适用于技能已安装到项目的 `.agents/skills/` 的情况。从技能集合仓库根目录运行时，将脚本路径改为 `proof-artifacts/scripts/render_case.py`，并传入实际用例目录。脚本在用例目录新建 `README.md`，并保留现有文件。非 UTF-8 正文的原始字节可从 HTTP 文件查看。

```bash
python3 .agents/skills/proof-artifacts/scripts/render_case.py proof-artifacts/run-01/case-01
```

在用例页写明预期行为和实际判定。有终态事件的协议要核对业务终态。涉业务数据时，用既有数据做独立对账，列明口径和可分享的参考值。用例涉及持久化时，记录实际回查和保存结果。

## 交付检查

- 从索引逐条打开审阅页，确认能同页核对路径、查询和 JSON 参数及响应。抽查页内参数与请求文件一致。
- 核对发出的用例与收到的响应一一对应。检查流是否完整，以及业务终态、返回的数据和副作用是否符合预期。
- 以 Markdown、Hurl 和完整 HTTP 文件作为审阅入口。摘要和工具生成的 JSON 报告供补充或后续处理。
